# Changelog

Each release records concrete behavior changes, verification, and relevant limitations. Entries for 0.1.0–0.3.1 were expanded retrospectively from their retained startup guides and the 0.3.1 verification report. Historical interface labels and defaults below describe those releases; 0.4.0 replaces several of them. Exact older release dates and unrecorded test counts are intentionally omitted.

## 0.6.0 — 2026-11-11

Fixes the bugs found in a line-by-line review of 0.5.3 and in earlier development notes, and adds the planned features. Fictional data only throughout.

- **Fixed (high): generated R/SAS code now repeats type changes on ID, additional-key and time columns.** The cleaning code assumed matching keys are never rewritten, but Change variable type and the numbers prompt do rewrite them. A `visit_date` time column converted with `M/d/yyyy` made R's final `as.Date()` fail or read year 0003 (long), every wide column NA (wide), and SAS read missing; a padded time converted to Number (`01` → `1`) gave all-NA wide columns; a response filter on a converted key dropped every row in R. Each key conversion is now written in step 2 as canonical text — `as_text(as.numeric(x))`, `format(as.Date(x, "%m/%d/%Y"), "%Y-%m-%d")`, or true/false — so files combine on the same values the app uses, and the final step types them as before. SAS uses `put(input(x, informat), yymmdd10.)` / `best32.`. SAS also accepts `M/d/yyyy`, `d/M/yyyy` and `yyyy-M-d` patterns now (its MMDDYY/DDMMYY informats read one-digit months and days).
- **Fixed (high): Replace values no longer silently deletes filtered records.** Replacing `Spouse` → `Caregiver` on a person column filtered to keep {Patient, Spouse} removed every caregiver record from all layouts and exports. A response filter now follows the replacement: records that were kept stay kept (a replacement with a missing value keeps them via the missing option); a replacement of an excluded response does not bring it back. The History entry names the before/after values and says the filter was updated.
- **Fixed (high): Ctrl+Z / Ctrl+Y inside a text box undo the typing again**, not the last data change. The window-level shortcut ignored focus; Search rows, Search variables, dialogs' inputs and a grid cell being edited are now left to their own undo.
- **Fixed (medium): converting a key in only some files is reported.** `00001` → `1` in one file no longer matches `00001` in another; the preview's notice now says which value no longer matches and how to convert every file. Mixed key types without such a break stay quiet, as before. The R code now matches the app in this case too (it normalizes the converted file's key).
- **Fixed (medium): R ZIP exports keep the display names.** `NAME.csv` and the dictionary of an R export now use the names shown in WideLong — the same names `clean.R` produces — instead of 32-character SAS names (`walking_speed_mps__Mother__Month_3` became `…Mother__Month_` / `…Mother__Mon_2`). SAS and Other-software exports keep SAS-compatible names; the review shows which applies.
- **Fixed (medium): two-digit years are refused.** .NET, R and SAS switch centuries at different cutoffs (`05/12/55` could be 1955 in the app and 2055 in R). Date patterns must contain `yyyy`; the type dialog explains why and changes nothing.
- **Fixed (medium): undo snapshots share the unchanged original rows.** Each of the 12 undo levels copied every original value as well as the working rows. Originals are immutable after import, so copies (undo, redo, code plans, previews) now share them, roughly halving undo memory and copy time on large files.
- **Fixed (medium): response filters on a matching key extend to files imported later.** A key filter covered only the files loaded when it was made, so Informant rows from a later file came back. New files copy the rule when the existing files agree on it, and the status line says so.
- **Fixed (low):** importing the same file twice shows `data (2).csv` but the cleaning code still reads `data.csv`; `.tsv`/`.txt` files keep their extension when renamed. Unexpected errors show their message (never data or a stack trace) instead of only "could not be completed". SAS programs whose folder or file names contain `&`, `%`, `;`, quotes or parentheses use full single-quoted paths instead of the `folder` macro variable. **Cleaning code…** opens on R, the verified language. Row numbers are consistently data rows not counting the header (conversion previews, matching errors, Review matching and the cleaning code). Wide time columns follow the order values occur within each ID, so an ID without Baseline no longer puts `x__Month 3` before `x__Baseline`. A non-UTF-8 file (usually an Excel CSV) suggests choosing Windows-1252 instead of showing a decoder exception. R's `as_text()` helper trimmed nothing, so numbers it formatted carried leading spaces (affecting Search rows and mixed value columns); it now trims.
- **New: Save / Open recipe** (Recipe ▾). A `.widelong.json` recipe stores everything needed to rebuild the session from the original files — keys, kept/renamed variables, types, missing rules, mappings, response filters, corrections and recodes, scales, value labels, time order, layouts, sorting, names and filter rules — and no data rows. Opening finds each original (recorded path, then the recipe's folder, else asks), checks the columns, replays the steps, stops if a recorded single-value correction no longer finds its value, and reports changed row counts.
- **New: scale scores.** Right-click → **New scale score…**: numeric items of one file, reverse coding (lowest + highest − x), mean or sum, and a minimum number of answered items; item missing codes are excluded. The score is a derived Number column after the file's columns, recomputed after every change, editable or removable, and written into the R (`rowMeans`/`rowSums` with the minimum rule) and SAS (`n()`, `mean()`/`sum()`) cleaning code. Scores are formatted to 15 significant digits so R/SAS double arithmetic matches.
- **New: Qualtrics and REDCap presets.** Import detects Qualtrics exports (an `{"ImportId":…}` row) and skips their two description rows; the choice can be made explicitly. R and SAS skip the same rows (SAS refuses when those rows contain line breaks). `record_id`, `ResponseId` and `redcap_event_name` are recognized as ID/time.
- **New: variable summary in Review your export**: N, missing count and share, distinct values, minimum, maximum, mean, and checks (all or over half missing, one value only, numbers beyond 3 interquartile ranges).
- **New: value labels** (`1 = Strongly disagree`) for Text/Number variables, in the dictionary, as R factors in `import.R` (or a `labels` attribute when some values are unlabelled), as a `labels` attribute in `clean.R`, and as SAS formats in both SAS programs.
- **New: Order time values…** on a time column sets the wide column order explicitly; unlisted values follow the data order.
- **Repository:** the version is set once in `Directory.Build.props` and read from the assembly (it was hard-coded in seven places); builds go to `output/WideLong`. `Build.ps1 -Publish` makes `output/WideLong-0.6.0-win-x64.zip` with one self-contained `WideLong.exe` (58 MB; no .NET install needed). `.github/workflows/checks.yml` builds and runs every check with R on each push and pull request.
- Privacy/persistence: unchanged except the new explicit recipe file, which holds settings and steps but no data rows (typed correction/recode values and folder paths are included, and the save dialog says so). No network calls, telemetry or automatic saving. Only `-Publish` downloads anything (the .NET runtime packs, from nuget.org, at build time).
- Verification: Release build with zero warnings and zero errors. 120 automated checks passed (102 before), including 18 new ones and native R 4.5.2 replays of every new case — Date and padded-number time keys in long and wide, a filtered converted key, a partially converted ID, Replace on a filtered role, Qualtrics skipping, and scale scores (source and long) — each matching the application's output exactly. The self-contained publish was built and the 0.6.0 window started in synthetic-check mode. The CI workflow was written but not run here. Generated SAS (including the new scale, format and key-normalization steps) has still not been executed in SAS.
- Known limitations: scale items must be non-repeated columns of one file (score repeated items from a long file); value labels apply to Text and Number variables; the README still has no screenshot.

## 0.5.3 — 2026-11-07

- Renamed to **WideLong** (formerly Data Helper). The header shows "Wide" in the dark accent purple and "Long" in a lighter purple; the window title, dialogs, export READMEs and generated script headers use the new name. The program is now `WideLong.exe` in `output/WideLong-0.5.3`; the source folder (`app/WideLong`), projects (`WideLong.csproj`, `WideLong.Tests.csproj`), C# namespace and test environment variables (`WIDELONG_RSCRIPT`, `WIDELONG_STRESS_SUBSET`) use the new name. Entries below describe the app under its earlier name.
- Examples: every built-in example now has five fictional files. Health study adds Enrollment (one row per person) and Labs (one row per visit); School adds student details, behavior and reading logs; Shop adds returns, support tickets and loyalty details; Monthly reports covers January–May; Survey adds incentives and follow-up calls; Household adds contacts (ID-only) and person details (ID + person). All still combine and replay in R (see verification).
- Numbers detection (user request): after an import or an example opens, variables stored as text whose non-missing values are at least 80% numbers, with at most five distinct non-number codes (for example "not given"), are listed in one **Treat these as numbers?** prompt with **Yes, convert to numbers** / **No, keep as text**. Yes records ordinary Convert steps and adds the listed codes to that variable's missing values; nothing is converted on No. Values with leading zeros (IDs, ZIP codes) and numbers over 15 digits are never offered; matching keys are offered only when every file's values are already plain numbers (key text is never rewritten); repeated columns of one measure convert together or not at all (an earlier draft converted one survey wave and not the other, which the native R test caught).
- **Revert variable type** (right-click a variable in the sidebar or a column header): removes that variable's recorded type changes, restores its original text and its earlier missing-value rules, and keeps any response filter on the same records. For a matching key it reverts the key in every file. Refused, with an explanation, when later corrections depend on the converted type.
- **Filter responses…** (user request; right-click any variable): a checklist of every response with record counts, plus *(missing)*. Unchecked responses are removed from that file before files are combined, so every layout, the preview counts, matching review, exports and the R/SAS cleaning code leave them out. Example: unchecking Child under person in the Household example drops Child rows in Long (31 → 24 rows) and removes `__Child` columns from Wide. Filters on a matching key apply to that column in every file. Filtered variables show "· filtered" in the sidebar and "Filter responses… (active)" in menus. Repeated columns direct users to Filter rules instead. Wide exports previously created role columns from every role in a file even when filtered out; they now use only kept records.
- Fix (user report, again): a column-header drag image and drop line could stay on screen, surviving new data and Clear session. Cause found: a header click that the app handles for sorting never reaches the grid's own mouse-up, so the grid stayed "ready to drag"; holding the button later (for example selecting cells) and moving across the header row started a drag without mouse capture, and releasing outside a header never ended it. The app now clears that pending state after every handled header click, after any mouse release in the window, when the window loses focus or the mouse leaves it, and at every preview refresh, using the grid's own cleanup. Verified on screen: sort click, then a drag from a cell across the header row released in the sidebar, then a real header drag; no image remained and the column moved.
- Export page (user request): **Dataset name** names the ZIP and every file in it — `NAME.csv`, `NAME dictionary.csv`, `NAME import.R` or `NAME import.sas`, `NAME clean.R` or `NAME clean.sas`, `NAME README.txt` — with a live list of the files under the box. Choosing a different file name in the Save dialog renames everything to match. **Software** is R, SAS, or Other (CSV, dictionary and README only); only the chosen software's scripts are included. **Include the cleaning code** (on by default) adds the cleaning script; if it cannot be generated the review says why and the export continues without it. Both-layout ZIPs use `NAME_wide` / `NAME_long` in their subfolders. Calls without a name (tests, older code paths) keep the previous generic file names.
- Cleaning code rewritten (user request) to read like a hand-written cleaning script instead of a data specification plus a generic runtime. R and SAS share one outline: (1) read the original files with every column as text (R also checks each file's row count); (2) clean each file with a labelled comment per group of changes — renames, single-value corrections with the old value (`dem[12, "age"] <- 34  # was "340"`), recodes, type changes grouped by type with their missing codes, missing-value codes, response filters (`dem <- dem[dem$person %in% c("P", "S"), ]  # leaves out "I"`; SAS `if not (person in ('P', 'S')) then delete;`), and the kept variables; (3) combine the files — repeated columns to rows, one row per ID (+ person) (+ time) in first-appearance order, each file's variables matched on its own keys (SAS uses PROC SQL left joins), wide spreading, custom variable/value rows, or stacked files with `source_file`; (4) key types, column order, names, filter rules, Search rows and sorting. Only steps that change something are written (for example, missing codes that actually occur). Base R only; R ends with `prepared` and a commented `write.csv()`; SAS ends with `WORK.NAME` and a commented permanent-library copy. The generator replays every recorded step on the original rows before writing, as before, and still refuses unrecorded changes. The embedded R runtime template is removed.
- R reader: original files are decoded from their recorded encoding explicitly (UTF-8, Windows-1252, UTF-16 LE) so non-ASCII text reads correctly in any R locale; one-column files keep records whose only value is empty.
- Wording: the cleaning-code window describes the new scripts; the Filter responses dialog explains that records are removed before files are combined.
- Privacy/persistence: unchanged. Detection, filters and naming are in memory; cleaning scripts contain local paths and explicitly corrected/recoded values, as before, and are written only by an explicit export or save.
- Verification (on the development PC, fictional data only): release build succeeded with zero warnings and zero errors. 100 automated checks passed (96 from 0.5.2, updated for the new script text, plus 4 new: response filters across layouts and in R/SAS text, numbers detection and revert, named export bundles, and a native-R case set). 55 native R 4.5.2 replays ran the generated scripts and matched the application's output exactly, including every layout of all six examples, response filters in Long and Wide, detected numbers in the Survey example, numeric IDs, compound ID + person + time keys, stacking, filters, sorting, renames, encodings and empty sources. Visual check in the 0.5.3 window: Survey example showed the numbers prompt and converted on Yes; Household example person → Filter responses… → unchecking Child gave 24 rows and "· filtered"; export page listed household.csv, household import.sas, household clean.sas and household README.txt live, and the review showed the same names (export cancelled; nothing written).
- Known limitations: generated SAS has still not been run in SAS. The SAS search-rows step compares SAS-formatted values. Chained type changes between Number, Date and Boolean are written for R only. In R, blank lines inside quoted multi-line values of one-column files are not preserved. The numbers threshold (80%, five codes) is fixed.

## 0.5.2 — 2026-11-07

- Fix (user report): dragging a column header left the floating copy of the header and the blue drop line stuck on screen, and the column did not move. 0.5.1's capture fix released the header's mouse capture on every mouse-up, including the end of a drag; WPF finishes a column drag only when the captured header receives the release, so the release went to the floating image instead. Drags are now left to the grid, and any leftover header capture is cleared after the grid has handled the release. Header clicks still sort as in 0.5.1, and a later click never goes to a previously clicked header.
- Faster, leaner combined layouts for wide files with many people, roles and times:
  - Cells for values a record does not have are now one shared, immutable empty cell instead of a new object each. Most combined cells are such gaps when many wide files are matched.
  - Wide (one row per ID): each ID's values are indexed by variable once, instead of rescanning every record of that ID for every output column. Conflict detection (a variable changing within one wide cell) is unchanged.
  - Custom variables (chosen rows): a record's context columns are looked up once and shared by all of its stacked rows, instead of once per stacked variable.
  - Measured on a larger multi-file test set (about 1,600 variables; 18 files): Wide built in 1.6–5 s instead of 17 s; stacking every repeated variable into rows built in about 4 s and 1.0 GB instead of 62 s and 1.8 GB; the long layout used about 0.2–0.4 GB instead of 0.5 GB.
- The in-memory preview cache keeps at most three layouts as before, but now releases older ones once the cache holds more than about 12 million cells. A single long view of a large study can exceed half a gigabyte, so three were held regardless of size before.
- Verification tooling: `Build.ps1 -StressData <folder>` runs an optional pressure test on a folder of the user's own CSVs kept outside this tree (see README). An independent oracle checks every combined cell against its source record (value, missing status, ID, additional key, time and repeated-column label) and requires every kept source value to appear, across raw, mapped and numeric-typed sessions; long, wide, custom-row and stacked layouts; three matching rules with deliberately incomplete files; multi-column numeric sorting; AND/OR rules and their complement; 40 seeded random file combinations (with and without the additional key); R and SAS export bundles read back in R; R/SAS code plans; and native R replays. The native-R replay helper is now shared by the synthetic suite and the stress run (`tests/RReplay.cs`) rather than duplicated.
- Findings from the pressure test that needed no code change: duplicate keys when files with several people per ID are matched without the additional key, and repeated variables whose columns have different types, are both refused with the existing explanatory messages; IDs that use different numbering schemes in different files are reported by the matching notes and coverage figures.
- Privacy/persistence: unchanged. The stress test reads only the folder passed to it and writes only to the stress output folder; the application itself still writes nothing except explicit exports and code saves.
- Verification: the release build succeeded with zero warnings and zero errors. All 96 synthetic checks passed, including native R 4.5.2 replays through the refactored shared helper. The pressure test passed 43 of 43 checks on the larger test set (not included). These included: every-cell oracle checks across all layouts; 66 combinations built and verified, with the rest refused for valid reasons; R and SAS bundles read back in R at 6,282 × 421 and 285 × 4,354; and six native R replays (raw long, typed long, wide, filtered, custom rows, stacked) on a six-file subset. An earlier run also replayed the full long layout (about 10 million cells) exactly in native R in 477 s. Visual check in the 0.5.2 window with the fictional Household example: dragging a column moved it and cleared the drag image; header clicks then sorted person and household_name in order; dragging a sorted column before another swapped their priorities.
- Known limitations: stacking every repeated variable of a very wide study into rows still produces hundreds of thousands of rows with all context columns (about 1 GB in that test). Choose fewer row variables for such data. SAS execution remains unverified.

## 0.5.1 — 2026-11-07

- Preview paging: the grid draws one page of rows (100 by default; 50, 100, 250, 500 or 1,000 under **Rows shown**) instead of every row. « ‹ Previous / Next › » and Ctrl+Page Up / Ctrl+Page Down move between pages; the footer reads, for example, "Rows 1–100 of 1,800". Sorting, Search rows, filter rules, counts, cleaning code and every export still use all rows. Cell edits and matching-diagnostic navigation map page positions back to the full view, so an edit on page 3 changes the correct source record and diagnostics jump to the page holding the problem record.
- Faster sheet changes: the merged (unsorted, unfiltered) view for each layout/file is cached in memory, up to three at a time. Sorting, Search rows, filter rules, renaming, column moves and paging reuse it instead of copying the session and rebuilding every cell; switching back to a recently viewed layout or file is immediate. Any data change (edit, recode, type change, keep/unkeep, matching settings, mappings, missing rules, undo/redo, import, example, clear) discards every cached view before the next preview, including when a newer preview supersedes an unfinished rebuild. Caches are never written to disk and are cleared with the session.
- Further speedups: preview snapshots no longer copy original rows; numeric sort keys are parsed once per row instead of on every comparison; unchanged grid columns are reused and only their headers redecorated; column-order reconciliation uses a set rather than repeated list scans; header and sidebar right-click/hover menus are built when opened rather than for every variable on every refresh; collapsed files build their sidebar variable lists only when expanded; the sidebar variable search waits 200 ms after typing before redrawing; the grid recycles row containers.
- ID can be numeric. The combined ID, additional-key and time/grouping columns previously were always Text, so a numeric ID still sorted as 1, 10, 2 and exported as character. They now take their source columns' type when every file agrees (time also requires repeated-column grouping labels to be canonical values of that type); otherwise they stay Text and the notice names each file's ID type and how to convert them together. **Change variable type…** is now available on the combined key headers and, for a key column in the sidebar, offers "Apply to the ID column in every file" (on by default) so keys keep matching. Conversion is refused when distinct values would collapse into one (for example 007 and 7, which would merge different records) or when a key value equals a missing-value code; the dialog also counts leading-zero loss and values over 15 digits. Numeric IDs sort numerically in the preview and exports, the dictionary records Number, and the generated R/SAS code types the ID as numeric through the existing recorded Convert step.
